# FOURFOLD · 네컷모먼트

촬영 → 네 장 선택 → 프레임·필터·문구 → 이미지 표시 → PNG 다운로드.
서버와 API 키가 필요 없는 정적 웹 앱입니다. 사진은 브라우저 안에서만 처리합니다.

## GitHub Pages에 올리기

1. ZIP을 풀고 **index.html과 나머지 파일들을 GitHub 저장소 루트**에 올립니다. 폴더 안에 한 번 더 넣지 마세요.
2. 저장소의 **Settings → Pages**를 엽니다.
3. **Source: Deploy from a branch**를 선택합니다.
4. **Branch: main**, **Folder: / (root)**로 저장합니다.
5. 배포가 끝나면 제공되는 HTTPS 주소를 휴대폰 Safari 또는 Chrome에서 직접 엽니다.

HTML/CSS/JavaScript를 그대로 제공하므로 npm 설치나 빌드 과정이 없습니다.
모든 파일 경로가 상대 경로여서 사용자 페이지와 프로젝트 페이지 모두 사용할 수 있습니다.

## 파일

- `index.html`: 화면 구조
- `styles.css`: 모바일·데스크톱 스타일
- `app.mjs`: 촬영, 파일 선택, 편집 상태, 다운로드
- `core.mjs`: 템플릿 25종·프레임·필터·인화 규격 정의, 자르기와 배치 계산
- `renderer.mjs`: 미리보기·완성 이미지 공통 합성
- `artwork.mjs`: 레퍼런스의 리본·풍선·케이크·선물·하트·고깔·안경을 사진 뒤에 합성
- `img-ref/IMG_6795.png`: 템플릿에 사용하는 원본 일러스트 시트 (배포 시 반드시 포함)
- `img-ref/IMG_6793.png`: `다인이의 생일` 손글씨 원본 (배포 시 반드시 포함)
- `print.mjs`: 인화용 PNG에 300dpi 해상도 정보 기록
- `sample.jpg`: AI로 생성한 미리보기 예시 사진
- `.nojekyll`: 정적 파일 직접 제공 설정
- `bump.sh`: 배포 전 캐시 버전 올리기

## 템플릿

크림색 종이와 핑크·블랙 색연필 그림을 활용한 **리본 파티·생일 케이크·하트 레터·파티 티켓·파티 다이어리** 5종이 먼저 표시됩니다. 기본 템플릿은 리본 파티, 기본 프레임은 크림 페이퍼입니다. 원본 레퍼런스의 그림을 로컬에서 읽어 종이 배경을 제거하고 사진 뒤에 배치합니다. 새 템플릿의 주요 요소는 가장자리와 상하단에 두어 사진을 가리지 않습니다.

기존 세로형 8종(클래식·라운드·필름롤·티켓·미니멀·도트·스트라이프·다이애고널),
정사각형 계열 10종(그리드·보더리스·윈도우·폴라로이드·오버랩·아치·더블·모자이크·매거진·하프),
가로형 2종(포스트카드·가로배너)도 유지됩니다. 모든 템플릿은 사진 네 장을 사용하며 프레임 색·필터와 자유롭게 조합됩니다.
좌표는 `core.mjs`에 "가로 폭 = 1" 비율로 정의되어 있어 값을 추가하면 템플릿이 늘어납니다.

완성 이미지의 제목은 참고 이미지의 **다인이의 생일** 손글씨를 그대로 사용합니다. `생일`은 원본 핑크색이며, 어두운 프레임에서는 이름만 밝게 표시합니다. 날짜는 **2025.09.22**로 고정되고 초기화해도 유지됩니다. `생일 날짜 넣기`로 표시 여부를 바꿀 수 있습니다.

## 포토 프린터 인화

미리보기와 PNG는 선택한 인화지의 비율을 똑같이 사용합니다.

| 인화지 | 비율 | 저장 크기 |
| --- | --- | --- |
| 4 × 6인치 (기본) | 2:3 | 1200 × 1800px |
| 5 × 7인치 | 5:7 | 1500 × 2100px |
| 6 × 8인치 | 3:4 | 1800 × 2400px |

모두 300dpi이며 PNG의 `pHYs` 청크에도 기록합니다. 전체 템플릿을 비율대로 축소해 인화지 안에 배치하고, 가장자리에 용지 폭의 최소 3.5% 여백을 둡니다. 세로 스트립이나 가로 템플릿은 남는 공간을 선택한 프레임 색으로 채우므로 디자인이 잘리지 않습니다. 각 사진은 기존처럼 사진 칸에 맞춰 가운데를 기준으로 자릅니다.

프린터 설정에서도 같은 용지 크기를 선택하세요. 실제 프린터의 무테 인화 확대·재단 범위에 따라 가장자리 결과가 달라질 수 있습니다.

## 배포할 때 (캐시)

휴대폰 브라우저는 `app.mjs` 같은 파일을 오래 붙잡고 있어서, 파일을 바꿔도 예전 코드가 그대로 도는 일이 있습니다.
그래서 모든 파일을 `app.mjs?v=2`처럼 버전을 붙여 부릅니다. **코드를 고쳤으면 푸시 전에 버전을 올리세요.**

```sh
sh bump.sh
```

`index.html`, `app.mjs`, `renderer.mjs`의 `?v=` 숫자가 함께 올라가고, 브라우저는 새 주소를 새 파일로 받습니다.
`index.html` 자체는 GitHub Pages 캐시(약 10분) 때문에 늦게 반영될 수 있습니다. 바로 확인하려면 주소 끝에 `?v=새번호`를 붙여 여세요.

## 사용하기

- 카메라를 허용하고 3·5·10초 간격으로 찍습니다. **기본은 4장**이며 8장을 선택할 수도 있습니다. 처음부터 다시 시작해도 4장으로 돌아옵니다.
- 또는 앨범 사진을 최대 8장까지 불러옵니다. 사진당 20MB, 48MP 이하를 지원합니다.
- 처음 네 장이 자동 선택됩니다. 선택한 사진을 다시 누르면 해제됩니다.
- 선택한 썸네일의 좌우 버튼으로 순서를 변경합니다.
- 인화 크기 3종, 템플릿 25종, 프레임 11색, 필터 5종, 문구, 날짜 표시를 선택합니다.
- **이미지 완성하기**를 누르면 실제 완성 이미지와 다운로드 버튼이 나타납니다.
- PNG로 저장합니다. 선택한 인화 규격에 맞는 픽셀 크기와 300dpi 정보로 내보냅니다. 출력 해상도가 원본 디테일을 추가하지는 않습니다.

## 휴대폰에서 확인할 점

- 카메라는 HTTPS 접속과 사용자 권한이 필요합니다. 메신저 안의 브라우저에서 안 되면 Safari·Chrome으로 직접 열어주세요.
- iPhone에서 다운로드가 사진첩 대신 파일 앱에 저장될 수 있습니다. 완성 이미지를 길게 눌러 저장하거나 파일 앱에서 사진으로 저장하세요.
- 브라우저에서 열리지 않는 HEIC 사진 등은 JPG·PNG로 변환한 뒤 불러옵니다.
- 화면 잠금이나 앱 전환 시 촬영을 중단합니다. 이미 촬영한 사진은 현재 페이지에 남습니다.
- 새로고침하거나 탭을 닫으면 작업이 사라집니다. 완성본을 먼저 다운로드하세요.
- 예시 사진은 사용자의 완성 이미지에 포함되지 않습니다.

## 확인한 범위

템플릿 25종 × 인화 규격 3종의 비율과 사진 네 장의 위치·순서, 새 템플릿 5종 × 프레임 11색의 합성, 3개 인화 규격의 실제 PNG 다운로드를 Chrome에서 검사했습니다. 320·390·768·1024·1440px 화면의 가로 넘침, 초기화 후 기본값, 가상 카메라의 기본 4장 촬영도 확인했습니다.
실제 iPhone·Android 카메라와 저장 흐름은 기기별 확인이 필요합니다.
선택적 WebMCP 인터페이스는 지원 브라우저에서만 동작하며 실행 검증은 하지 못했습니다.

인화 크기와 PNG 해상도 메타데이터 자동 검사는 `node --test tests/print.test.mjs`로 실행합니다. 실제 인쇄 결과는 포토 프린터에서 확인해야 합니다.

## PC에서 실행

ZIP을 푼 디렉터리에서:

```sh
python3 -m http.server 8000
```

PC에서 `http://localhost:8000`을 엽니다. 휴대폰에서 PC의 HTTP IP 주소로 접속하면 카메라가 제한되므로 휴대폰은 배포된 HTTPS 주소를 사용하세요.
